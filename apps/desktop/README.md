# CS2 Farm Manager Desktop

Desktop-оболочка **существующего** CS2 Farm Manager. Сохраняет Next.js Dashboard и сервер PostgreSQL/Redis для масштабируемого развёртывания. Небольшая автономная Windows-установка использует реальный backend, SQLite WAL и устойчивую локальную очередь: Redis, PostgreSQL, Python, Node.js и Docker пользователю устанавливать не требуется. Windows runtime и Node поставляются внутри установщика; Electron создаёт собственные окна.

## Работа пользователя

1. Откройте `CS2-Farm-Manager-Setup.exe`, пройдите обычный графический мастер и запустите ярлык.
2. В первом запуске выберите главный компьютер, дополнительный компьютер или подключение к существующему HTTPS-серверу.
3. Для главного компьютера создайте администратора: минимум 14 символов пароля. Создание БД, миграции, запуск API, worker и Dashboard выполняются автоматически.
4. Добавляйте аккаунты в сохранённой панели. Для обычного Steam требуется ручная авторизация владельца в официальном клиенте.
5. Для другого ПК включите защищённые подключения в System Management. Выберите IP из списка реальных интерфейсов, явно подтвердите включение и при необходимости разрешите собственный HTTPS-порт через **графические настройки Windows Firewall**. Приложение само не открывает порты.
6. На другом ПК установите `CS2-Farm-Agent-Setup.exe`, введите HTTPS-адрес и одноразовый код из Nodes либо вставьте ссылку `cs2farm://enroll`. Для локального CA скопируйте публичный сертификат из System Management главного компьютера. Проверка TLS не отключается.
7. На компьютере агента выберите официальные `steam.exe` и `cs2.exe` кнопками файлового диалога в System Management, если автоматическое обнаружение не нашло их. Произвольный EXE выбрать нельзя.

Для подключения оконной панели к серверу с частным CA доверие Windows к этому CA нужно установить стандартным **графическим мастером сертификатов**. Сертификат сервера и имя проверяются, обработчика обхода `certificate-error` нет. Публичный HTTPS-сервер использует обычную системную цепочку доверия.

## Управление системой

Меню приложения, значок трея и Settings → System Management открывают локальное окно управления. В нём доступны:

- реальные состояния backend, БД, worker/очереди и Dashboard; сведения о недостающих файлах поставки;
- ограниченный автоматический перезапуск после сбоя и ручной перезапуск;
- просмотр ошибок, проверка соединения и расположение данных;
- создание резервной копии и восстановление через стандартные файловые диалоги; восстановление останавливает компоненты и аннулирует прежние сессии входа;
- HTTPS-доступ для агентов с локальным CA и явным согласием пользователя;
- Telegram: токен, chat ID и важность через GUI, Windows DPAPI для сохранения секрета; токен не возвращается в интерфейс;
- выбор разрешённых Steam/CS2-приложений на компьютере агента;
- автоматический запуск после входа пользователя Windows и поведение закрытия в трей;
- проверка обновлений через подписанный Ed25519 manifest HTTPS, когда издатель настроил канал.

Если канал обновлений не настроен, приложение прямо сообщает, что проверка не выполнялась. Никакой фиктивной «актуальной версии» нет. Перед запуском загруженного установщика проверяются подпись издателя manifest, SHA-256 файла и закреплённый хост. Windows SmartScreen не обходится; Windows-подпись установщика — отдельная цепочка доверия.

При включённом сворачивании закрытие окна оставляет приложение в трее. «Выход» корректно останавливает дочерние процессы. При отключённом сворачивании закрытие завершает приложение. Обычный автозапуск здесь — **после входа пользователя**, а не служба до входа в Windows: это сохраняет интерактивный сеанс Steam. Существующая Windows Service агента из прежнего проекта не удаляется.

## Безопасность оболочки

Локальный мастер работает с `contextIsolation`, `sandbox`, `nodeIntegration=false` и CSP без внешних соединений. Привилегированный IPC доступен только точному локальному файлу мастера и его WebContents. Dashboard получает отдельный минимальный preload с одной операцией открытия System Management. Окно удалённого HTTPS-сервера вообще не получает preload.

Supervisor проверяет, что порты свободны, не подключается к чужому локальному backend и сверяет случайный идентификатор процесса в readiness. Сеть по умолчанию — только loopback. Пароль администратора и одноразовый код передаются runtime через stdin и не сохраняются в `desktop.json`. Фоновые компоненты запускаются с `windowsHide`, без shell, с фиксированными аргументами. Остановка API/агента идёт через приватный stdin, с ограниченным принудительным завершением только собственных процессов при зависании.

## Проверки разработчика

Команды ниже предназначены для сопровождения исходного кода, не для конечного пользователя.

- `npm test --prefix apps/desktop`: **10 прошедших Node-тестов**. Конфигурация, исключение секретов, HTTPS/deep links, подпись обновлений, PNG CRC, занятые порты, реальные процессы тестового fixture с проверкой ownership/перезапуском/остановкой.
- `node apps/desktop/test/run-runtime-integration.cjs`: настоящий Supervisor + реальный Python API + SQLite + production Next. **8/8 проверок**: создание администратора/БД без Redis, готовность, проксирование и запись аккаунта, backup, полный restart с сохранением, аннулирование сессий и restore. Требуется предварительная сборка Next с `API_URL=http://127.0.0.1:17831`.
- `node apps/desktop/test/wizard-browser.cjs`: Chromium проверяет шесть шагов HTML-мастера, очистку пароля и System Management. **IPC явно заменён тестовым адаптером**; это не проверка Electron или Windows.

Машинные результаты и снимок окна: `test/results/`. В Linux успешно прошли реальные серверные проверки и браузерный HTML-поток. Native Electron, установка на чистую Windows 11, графический UAC, отсутствие консольных окон на Windows, автозапуск после реальной перезагрузки и деинсталляция в Windows Settings **не объявляются проверенными**. Для них подготовлена Windows CI в `build/windows` и `.github/workflows/windows-desktop.yml`; результаты Windows CI считаются доказательством только после фактического запуска workflow.

Готовые экспериментальные EXE получены настоящим NSIS cross-build. Проверка полной CRC, PE и контрольных сумм: `docs/windows-artifact-verification.json`. Это не подтверждение запуска на Windows. Текущие установщики не подписаны.
