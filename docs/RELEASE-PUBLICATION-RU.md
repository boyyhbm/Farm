## Будущие версии

Workflow `.github/workflows/windows-export-verified.yml` автоматически запускается после успешного **Windows desktop installers**. Разрешены собственный `main` и теги `desktop-v<version>`; PR, посторонние репозитории и неуспешные прогоны не публикуются. Для повторного запуска доступен графический **Actions → Publish verified Windows pre-releases → Run workflow** с ID сборки и проверки.

Перед публикацией обязательны успешная установка обоих исходных EXE, полный smoke, две реальные SCM-службы без skip, отсутствие source overlay и совпадение размеров/SHA-256. Затем сканируются распакованные установщики, подготовленные вложения и исходники точного проверенного commit. При обнаружении секрета публикация блокируется; значения секретов не попадают в отчёт.

Версия читается из `apps/desktop/package.json` проверенного commit. Workflow подготавливает Draft `v<version>`, загружает оба EXE и отчёты, затем переводит его в публичный **Pre-release**. Он не объявляется стабильным Latest. Уже опубликованные EXE не заменяются: повтор допустим только при совпадении commit, размеров и SHA-256. Для другой сборки той же версии требуется изменить версию.

Последний этап полностью скачивает оба публичных EXE без авторизации, сравнивает SHA-256 и сохраняет аудит **Release-publication-audit**. К релизу прикрепляются `release-security-scan.json` и `release-provenance.json`. При отказе GitHub в создании исторического тега workflow выдаёт ошибку и не подменяет проверенный commit текущим `main`; владелец может предварительно создать нужный Draft через GitHub Releases.

Проверки новых инструментов: **9 tests passed**; workflow прошёл `actionlint`. Повторный запуск издателя на уже опубликованном v0.4.0 проверяет весь путь проверки и сохранение существующих EXE. Создание первого релиза следующей версии проверяется при её фактическом выпуске.
