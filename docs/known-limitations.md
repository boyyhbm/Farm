# Проверенные границы реализации

Серверный MVP дополнен desktop-кодом и Windows CI в boyyhbm/Farm. Фактические результаты native Windows-прогонов приведены в отчёте; проверка CRC/PE или успешная компиляция не заменяет проверку установки. Текущие установщики не подписаны и остаются экспериментальными. Полный список текущих проверок: [windows-desktop-verification.md](windows-desktop-verification.md).

- На Windows Server 2022 CI проверены реальные NSIS EXE, LocalSystem-службы, DPAPI, HTTPS/WSS, synthetic-задания и деинсталляция. Чистая Windows 10/11, настоящая перезагрузка, два физических ПК, WTS запуск Steam/CS2, физические GPU/температурные датчики, интерактивные UAC/SmartScreen и SCM recovery после принудительного падения процесса требуют отдельной приёмки. AUTO_START и recovery policy настроены, но настройка не заменяет тест ОС после перезагрузки.
- На узел планировщик выдаёт одну активную сессию любого типа. Движок и агент поддерживают независимые тестовые экземпляры, но центральный планировщик намеренно ограничен одним заданием на узел. Несколько Steam-аккаунтов одновременно в одном рабочем столе не поддерживаются.
- Steam-аккаунт в реестре не означает авторизацию клиента. Агент запускает локально разрешённый Steam/CS2 без передачи паролей и без автоматического переключения Steam-пользователя. Оператор обязан проверить текущую ручную авторизацию. Prime — ручное подтверждённое поле; недоступные сведения неизвестны.
- Нет автоматизации официальных матчей, получения XP/наград, обходов VAC, Steam Guard или CAPTCHA. Gameplay Test Engine — синтетическая симуляция конечного автомата в отдельном процессе; это не игровой бот CS2.
- Доступность конкретного реального инвентаря Steam не подтверждена без предоставленного публичного аккаунта. Обработчики проверены с явно внедрённым тестовым HTTP transport. Публичные Community endpoints не имеют SLA, могут изменяться и ограничивать запросы. Полная оценка неизвестна, если хотя бы одна цена отсутствует.
- Точные актуальные UTC-границы недельного сброса CS2 не установлены по надёжному доступному источнику: периоды не генерируются автоматически. Оператор регистрирует проверенные границы и источник. Новые предметы не подтверждают Weekly Care Package.
- Telegram не отправлялся на реальный chat: токен и chat_id не предоставлены. Реализованы outbox, дедупликация, важность, 5 попыток с backoff и ежедневный отчёт.
- Финансы только USD, введённые продажи означают фактические денежные поступления. Steam Wallet не считается выводимыми деньгами. Нет FX, себестоимости каждого предмета и модели будущего cashflow: прогноз окупаемости остаётся неизвестным.
- Расписания используют интервалы в секундах, FIFO/priority/round-robin распределение узлов; нет произвольного cron и автоматической авторизации/ротации пользователей Steam.
- При потере агента активная сессия резервирует узел как UNKNOWN до подтверждения состояния/остановки. Автоматический перенос на другой узел мог бы дублировать запуск, поэтому не выполняется. Если диск агента потерян вместе с журналом команд, требуется вмешательство оператора; ложный успех не выставляется.
- Масштабирование реестра измеряется отдельно от запуска CS2. Нагрузочная проба не доказывает эксплуатацию сотен физических ПК или 5000 игровых клиентов.
- Docker API image собран. Полный одновременный запуск контейнеров в данной 8GB/VFS среде упёрся в ENOSPC; проверка всей Compose-топологии на обычном Docker-host остаётся необходимой. PostgreSQL и Redis здесь работают в контейнерах, приложения и Celery проходят проверки локальными процессами.
- TLS production-конфигурация Caddy проверена синтаксически. Для публичного сертификата нужны ваш домен/DNS и доступные порты; localhost использует локальный CA, который нужно доверить. Проверка боевого HTTPS с Windows агентом не выполнена.
- Desktop System Management настраивает Telegram через GUI с DPAPI; серверный режим сохраняет конфигурацию через окружение. Пароли Steam и произвольные команды ОС не принимаются.

- Desktop SQLite — одно небольшое локальное развёртывание, не замена распределённой PostgreSQL/Redis-инфраструктуры. Локальная очередь сохраняется между запусками; просроченные lease восстанавливаются без ложного успешного выполнения.
- Manager работает после входа пользователя. Agent предлагает настоящую службу LocalSystem через UAC и отдельную SYSTEM-привязку; интерактивный режим сохранён. Работа после настоящей перезагрузки ОС подтверждается отдельно на физическом стенде.
- Канал desktop-обновлений издателя пока не опубликован. Проверка сообщает «не настроен», а не ложное «версия актуальна».
- Установщики могут быть неподписанными до настройки сертификата издателя. SmartScreen и его репутация не обходятся. Чистая Windows 11, реальная перезагрузка, второй физический ПК ещё требуют выполнения. Состояние проверки нативного деинсталлятора указано в отчёте CI.
