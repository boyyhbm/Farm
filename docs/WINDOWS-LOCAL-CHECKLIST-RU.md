# Проверка на вашем Windows 10/11 без терминала

CI Windows Server и два агента на одном CI-хосте не подтверждают этот список.
Отмечайте пункты только после выполнения на своих компьютерах.

- [ ] На чистой Windows 11 x64 без Python, Node.js и Docker запустить `CS2-Farm-Manager-Setup.exe`.
- [ ] Пройти обычный мастер, проверить ярлыки рабочего стола и меню «Пуск».
- [ ] Создать администратора в графическом мастере; дождаться Backend, базы, очереди и Dashboard.
- [ ] Через System Management нажать «Проверить соединение»: просмотреть каждую проверку, сохранить JSON-отчёт.
- [ ] Добавить 10 аккаунтов, группы, заметки, расписание, запись награды и расход. Записать контрольные значения.
- [ ] Закрыть приложение через трей, запустить снова: сравнить данные.
- [ ] Включить автозапуск, перезагрузить Windows: проверить запуск панели, данные и очередь.
- [ ] В System Management включить HTTPS на конкретном сетевом адресе. Сверить CA и адрес. Разрешить доступ Windows Firewall только для доверенной сети, если это нужно. Приложение само правила не меняет.
- [ ] Скачать Agent EXE из Nodes; установить на двух других Windows-ПК.
- [ ] На каждом ПК создать отдельный одноразовый код, импортировать публичный CA и выбрать фоновую службу. Подтвердить Windows UAC.
- [ ] Проверить два разных Node ID, свежие heartbeat и настоящую телеметрию.
- [ ] Закрыть окна Agent: узлы должны продолжать передавать телеметрию как службы.
- [ ] Перезагрузить оба ПК: проверить heartbeat до запуска Agent GUI. Для Steam/CS2 требуется вход пользователя и ручная авторизация Steam.
- [ ] Отправить по разрешённому synthetic test заданию на каждый узел: проверить одновременное RUNNING, завершение и метрики.
- [ ] Проверить остановку, последовательную очередь и round robin; одно задание не должно запускаться дважды.
- [ ] Временно отключить сеть одного узла: задание должно стать UNKNOWN, без ложного COMPLETED. Вернуть сеть, проверить сверку состояния.
- [ ] Установить следующую версию поверх предыдущей. Сравнить все контрольные данные. Совместимость каждой новой миграции проверяется отдельно.
- [ ] Проверить трей, уведомления, сворачивание, отсутствие постоянно открытых консолей.
- [ ] Удалить Agent через Windows Settings, подтвердить удаление службы через UAC. Убедиться в отсутствии службы в приложении Windows «Службы».
- [ ] Удалить Manager через Windows Settings. Проверить ярлыки и поведение выбора сохранения/удаления данных.

Установщики пока не подписаны Authenticode. Издатель может добавить подпись позднее; репутация SmartScreen и её диалоги не проверяются автоматическим CI. Приложение не изменяет настройки SmartScreen.

При ошибке сохраните диагностический JSON в System Management и сообщите шаг, текст ошибки и версию приложения. Отчёт диагностики не включает пароли, токены и содержимое базы.

## Protection 0.3.0

- [ ] Перед обновлением сохранить резервную копию через System Management. После обновления сравнить аккаунты, заметки, задания, награды, расходы и настройки.
- [ ] Открыть «Защита». Без Steam API key сведения VAC/Community/Game/Economy должны оставаться неизвестными; интерфейс не должен показывать выдуманные блокировки.
- [ ] Настроить свой ключ через графическую форму, выполнить проверку и сверить источник, время и фактические сведения со Steam. Для теста не требуется аккаунт с блокировкой.
- [ ] Вручную войти в официальный Steam на выбранном ПК. В Protection подтвердить SteamID и узел с ограниченным сроком. Проверить, что после истечения срока новое Steam/CS2-задание требует нового подтверждения.
- [ ] Подтвердить другой аккаунт на том же ПК: прежнее подтверждение должно отмениться, затронутое задание — безопасно остановиться. Не создавать параллельные конфликтующие Steam-сессии.
- [ ] Включить ручную паузу аккаунта и проверить запрет Steam/CS2-задания, диагностическое сообщение, инцидент и аудит. Снять паузу с явным подтверждением и основанием.
- [ ] Отключить сеть одного узла: сверить инцидент, устаревший heartbeat и UNKNOWN-сессию. После восстановления связи проверить сверку процессов и выполнение сохранённых остановок.
- [ ] При настроенном Telegram сверить доставку уведомления об инциденте и отсутствие секретов в сообщении.
- [ ] Под учётной записью viewer проверить невозможность изменения политик и состояния аккаунтов; operator не должен менять ключ или снимать административную паузу.

Реальные HTTP 429, блокировки и неверные учётные данные не нужно специально провоцировать в Steam. Эти ветви проверяются изолированными автоматическими тестами и не подменяют реальные статусы production.
