## Что проверяют сценарии защиты

Подтверждённые ограничения и неверные ответы Steam, недоступность API, 429 и общий cooldown, отказ ключа, ручной вход и его истечение, запрещённые операции, конфликтующие сессии, аварийная остановка и аудит проверяются автоматическими тестами. Сохранились проверки реестра 1200 аккаунтов и управления 24 узлами / 48 заданиями; это не замер 1200 работающих клиентов CS2.

Новые проверки покрывают локальную блокировку без связи, сохранение блокировки после перезапуска, перегрев/нехватку ресурсов через явно заданные тестовые показания, изоляцию исправного узла, проверку хешей, изменение игрового эталона, повреждение локального состояния, маркер неуспешного обновления, повторные сбои клиента и ограниченные повторы остановки. Отдельно проверено, что cached failure Manager нельзя обойти возобновлением очереди и одинаковые значения часов Windows не выбирают устаревший успешный результат. Возврат требует нового результата агента и не восстанавливает отменённые задания автоматически.

Первый полный успешный прогон Engine 2.0: [41924517752](https://github.com/boyyhbm/Farm/actions/runs/41924517752), исходники `706dcb43c59beae78a1342075624e274b1197e08`: Python 124 passed / 1 skipped; Node 13 passed; 22 проверки установщиков; 9 проверок установленного Manager; один полный сценарий двух настоящих SCM-служб, 0 skipped, 213.588 s. Это подтверждение той сборки, а не подмена проверки финального EXE.

По результатам неуспешных прогонов исправлены выбор последнего результата проверки при одинаковом времени Windows, ожидание первого настоящего измерения RAM, гонка короткого дочернего процесса между `psutil` и сохранённым handle. В [41926283029](https://github.com/boyyhbm/Farm/actions/runs/41926283029) все операции до последнего удаления прошли, но EXE Agent остался на диске. Добавлены ограниченные повторы удаления, диагностика оставшихся файлов/процессов и сохранение записи Windows Settings при неуспешном удалении. Неуспешные прогоны не считаются успешной приёмкой.

## Границы проверки

Steam-ответы проверены через явно заданный `httpx.MockTransport` только в тестах. Настоящий GetPlayerBans с ключом администратора, доставка Telegram в реальный чат и физический перегрев не проверялись. В production вымышленных банов, температур, подписей или вероятности блокировки нет.

Windows CI использует Windows Server 2022 x64 и две LocalSystem-службы на одном хосте. Это не два физических ПК. PATH smoke-процесса ограничен стандартными Windows-каталогами; используются встроенные runtime. Это не доказательство установки на чистой Windows 11. Установка NSIS выполняется в тихом режиме, поэтому интерактивные UAC/SmartScreen и визуальное отсутствие консолей требуют отдельной проверки.

Не выполнены: чистые Windows 10/11, фактическая перезагрузка ОС, два физических дополнительных ПК, обновление с ранее выпущенного EXE другой версии, подписанная Authenticode-поставка. Миграция старой схемы и переустановка той же версии проверяются отдельно и не заменяют обновление между EXE. Используйте чек-лист без командной строки.

Локальный неподписанный SHA-256-эталон обнаруживает расхождения, но не подтверждает издателя. Игровой эталон охватывает выбранные EXE/DLL и не является проверкой всех VPK/всех модификаций. Нет датчика — нет подтверждённой температуры. Неподписанная поставка не обходит SmartScreen. Ни один результат не является прогнозом или гарантией отсутствия VAC-бана.
