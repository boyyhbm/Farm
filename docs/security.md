# Модель безопасности

## Границы доверия

Управляющий сервер администрирует только зарегистрированные собственные узлы. Постоянный credential каждого агента имеет отдельную идентичность и может быть отозван. Одноразовый токен регистрации нужно передавать оператору узла по защищённому каналу. Токен не является паролем Steam.

Агент не предоставляет shell, удалённый PowerShell или передачу произвольного исполняемого пути. Путь к Steam/CS2 настраивается локально администратором ПК; команды сервера ограничены известными операциями и параметрами. Завершаются только процессы, которыми владеет агент. Повторная доставка команды с тем же ID не должна создавать второй процесс. Подписанные обновления доверяют локально настроенному публичному ключу издателя; храните приватный ключ подписи вне репозитория и управляющего сервера.

Windows Service работает в отдельном сеансе. GUI Steam/CS2 следует запускать агентом в интерактивном сеансе владельца; установка службы сама по себе не даёт поддерживаемый многопользовательский Steam. Пароли и секреты Steam Guard не импортируются и не хранятся в приложении.

## Панель и API

Секреты сервера находятся в `.env` (права 0600) или должны передаваться через ваш менеджер секретов. Ключи не передаются Next.js как `NEXT_PUBLIC_*`. Панель использует защищённую HttpOnly сессию и CSRF-токен для изменяющих операций, проверку Origin, RBAC admin/operator/viewer, хеши паролей и аудит команд. В production необходимо `SESSION_SECURE=true` и HTTPS. Нельзя считать localhost development override пригодным для публичного размещения.

Caddy закрывает HTTPS, запрещает embedding через X-Frame-Options, выставляет MIME-sniff protection/HSTS и маршрутизирует `/api`/`/ws` к внутреннему API. Доступ к reverse proxy должен идти по адресу, совпадающему с `PUBLIC_ORIGIN`. БД и Redis доступны только во внутренней Docker-сети; dev override публикует порты строго на `127.0.0.1`.

Журналы и Telegram не должны содержать токены, cookie, пароли или полные auth-заголовки. Администратор имеет право видеть запись аудита; не направляйте журналы в публичный сервис. Ссылки на профиль Steam и SteamID64 являются введёнными пользовательскими данными и обрабатываются как недоверенные строки.

## Эксплуатация

- Отключайте доступ скомпрометированного агента в Nodes и перевыпускайте его credentials.
- Не переносите `.env` через чат или Git. Меняйте секреты при утечке. В БД хранятся Argon2id-хеши паролей и SHA-256-хеши случайных токенов; восстановимых Steam-секретов нет. На Windows credential агента защищён DPAPI и ACL.
- Зашифровывайте и проверяйте резервные копии; секреты восстановления храните отдельно.
- Ограничивайте доступ к серверу, обновляйте зависимости и Windows; запуск агента не требует отключения антивируса или античита.
- Не используйте функции управления для обхода Steam Guard/CAPTCHA, автоматизации официальных матчей или выдачи наград. Тестовый движок изолирован от CS2.

Наличие этих механизмов не означает независимый penetration test или сертификацию. Требуется проверка физической установки Windows, полномочий службы, рабочего стола и цепочки сертификатов в вашей инфраструктуре.
