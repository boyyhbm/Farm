# Фактические проверки Windows Desktop

Дата: 2026-11-03. Разработка и проверки выполнены в Linux. Ни один непроверенный Windows-сценарий ниже не считается успешным.

## Исходный код и настоящие процессы

- Последний полный Python-прогон: **76 passed, 1 warning in 31.86s**. Предупреждение Starlette о будущем httpx2, не ошибка выполнения.
- **10 Node-тестов** desktop-компонентов: конфигурация без сохранения пароля/кода, HTTPS/CA, Ed25519, CRC изображения трея, выбор bundled runtime, собственные процессы, занятые порты, health identity, перезапуск и остановка. Runtime-fixture в unit-тестах явно тестовый и не поставляется пользователю.
- **8/8 реальных интеграционных проверок** Node Supervisor → Python API → SQLite/локальная очередь → production Next. Настоящие процессы создавали администратора и БД, записывали аккаунт через веб-прокси, выполняли backup, полный restart с сохранением данных, restore с отзывом старых сессий и завершение компонентов. [Отчёт](../apps/desktop/test/results/supervisor-integration.json).
- Реальный HTTPS listener с собственным CA: доверенный сертификат принимается, без CA соединение отклоняется; HTTPS cookie имеет Secure. Настоящий дополнительный процесс агента привязан одноразовым кодом, отправляет WSS-телеметрию и выполняет отдельный процесс тестового движка. Это один Linux-host, не второй физический Windows-ПК.
- Проверены конкурентное потребление одноразового кода SQLite (один успех, один отказ), lease локальной очереди, сохранение после перезапуска, безопасный отказ от ZIP traversal, откат обеих БД при сбое restore и UTF-8-пароли при принудительно заданной ANSI-кодировке канала.
- Chromium прошёл 11 разделов сохранённой панели, System Management, диагностику, CRUD аккаунтов и мобильную навигацию без ошибок API/браузера. [Результат](../tests/e2e/artifacts/dashboard-result.json).
- Шесть шагов HTML-мастера и очистка пароля проверены Chromium с **явно тестовым IPC-адаптером**. Это проверка формы, не работа Electron или установка Windows. [Результат](../apps/desktop/test/results/wizard-browser.json).
- Конфигурации electron-builder, YAML CI, Python spec и грамматика PowerShell проверены. Native CI ещё не выполнялась.

## Что ещё должно пройти на Windows

| Сценарий | Состояние |
|---|---|
| Установка на чистую Windows 11 | Не проверено |
| Запуск без системного Python/Node.js/Docker | Не проверено на Windows; компоненты включены в payload |
| Работа настоящего Electron-окна и трея | Не проверено на Windows |
| Создание БД/API/Dashboard при первом запуске | Реальная логика проверена Linux-процессами; нативный Windows-запуск не проверен |
| Второй физический ПК | Не проверено; HTTPS/WSS проверены отдельным реальным процессом |
| Автозапуск после перезагрузки | Не проверено; режим после входа пользователя |
| Удаление через Windows Settings | Не проверено; NSIS-деинсталлятор и регистрация включены |
| Отсутствие консольных окон на Windows | Не проверено визуально; собственные child process используют windowsHide/CREATE_NO_WINDOW |
| Работа SmartScreen/подписи | Защита не обходится; текущие cross-build установщики не подписаны |

Workflow [windows-desktop.yml](../.github/workflows/windows-desktop.yml) собирает выбранный embedded/frozen runtime и запускает реальные installation/smoke/uninstall проверки с PATH без Python/Node.js/Docker. Он работает на Windows Server 2022, **не заменяет чистую физическую Windows 11**. У проекта здесь нет Git remote или доступного Windows runner, поэтому workflow не запускался. Наличие подготовленного workflow не выдаётся за успешную Windows-проверку.

## Поставка и ограничения

Portable build использует настоящий Windows CPython 3.12.14 из проверяемого дистрибутива Astral/uv, Windows wheels по hash-lock, официальный Node.js по SHA256 и Windows Electron. NSIS собирает настоящий PE-установщик, не переименованный ZIP. Подробности сборки и контрольных сумм фиксируются после завершения упаковки в [windows-artifact-verification.json](windows-artifact-verification.json).

Для ограниченного диска использован повтор упаковки с общими hard-link входными файлами; сами готовые EXE содержат независимые полные payload. Исходный код сохранён. Build-time зависимости/кэши очищались для освобождения места, пользовательские базы PostgreSQL/Redis и исходники не удалялись.

Desktop — интерактивное приложение после входа пользователя. Прежняя Windows Service сохранена отдельно. SQLite предназначен для небольшого локального развёртывания; PostgreSQL/Redis/Celery остаются серверным вариантом. Канал подписанных desktop-обновлений издателя пока не опубликован: проверка отображает недоступность, не ложное «актуально». Ограничения Steam/Weekly Drops из [known-limitations.md](known-limitations.md) сохраняются.

## Полученные EXE

Оба NSIS compiler прогона успешно завершились. Manager: **443632991 bytes**, Agent: **204210771 bytes**. Проверены PE-заголовки, NSIS signature, полная длина контейнера и CRC32; файлы не усечены. Оба Authenticode certificate table пусты — установщики не подписаны. Подтверждено наличие настоящих x64 Windows CPython/Node в payload, совпадение серверных исходников и точное совпадение вложенного Agent Setup с отдельным файлом. Контрольные SHA256: [windows-artifact-verification.json](windows-artifact-verification.json).

При cross-сборке исправлены найденные проблемы: отсутствие package.json корня и явной версии Electron, невозможность стандартного NSIS uninstaller extraction без Wine, дефицит места и ANSI-кодировка приватного stdio. Использован настоящий MUI2/WriteUninstaller NSIS compiler; ZIP и Linux-бинарники не переименовывались в EXE. Установка/запуск на Windows всё ещё не выполнялись.

Дополнительно закрыты все временные SQLite connections до файловых операций backup/restore: Windows запрещает замену открытых DB-файлов. Отдельный regression-тест проверяет закрытие каждого дескриптора. Финальные NSIS используют независимые zlib-блоки для ограниченного scratch-space и быстрого открытия мастера; контрольные суммы относятся к этим окончательным EXE.
