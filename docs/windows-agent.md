# Windows Node Agent

## Назначение и границы

Агент предоставляет фиксированные операции `start`, `stop`, `restart_agent`.
Поддерживаются только локально настроенные Steam/CS2 и отдельный синтетический
тестовый движок. Входящие сообщения не могут указать исполняемый файл, shell,
произвольные аргументы, Steam-пароль или секрет Steam Guard. Вход пользователя
в официальный Steam-клиент выполняется вручную. Привязка Account ID является
учётной записью панели: агент не может подтвердить, что в Steam вошёл именно
этот пользователь. Оператор обязан проверить это перед запуском CS2.

Steam/CS2 требуют доступного интерактивного рабочего стола Windows. Служба
LocalSystem использует токен пользователя активной консольной сессии через WTS
и `CreateProcessAsUser`; при отсутствии входа в Windows команда вернёт ошибку.
Сначала используется приостановленное создание процесса и Windows Job Object,
затем поток возобновляется: дочерние процессы входят в управляемую группу.
Запуск нового Steam блокируется, если Steam уже работает; существующий клиент
не объявляется управляемым. Процессы, запущенные пользователем ранее, агент не
останавливает. На узле одновременно разрешается один интерактивный сеанс.

Служба, WTS и установщик требуют проверки на реальных Windows 10/11;
в предоставленном Linux-окружении они не запускались. Два Linux-агента проверены
с реальным API, PostgreSQL, Redis и Celery; это проверка оркестрации,
а не подтверждение работы на двух физических Windows-ПК.

## Установка Windows 10/11

Нужны Python 3.12+ (Python Launcher `py`), PowerShell 5.1+, права локального
администратора, HTTPS сервер панели с доверенным сертификатом и полный checkout
репозитория. Откройте PowerShell от администратора в корне репозитория:

```powershell
.\apps\windows-agent\installer\Install-Agent.ps1 `
  -ServerUrl 'https://farm.example.com' `
  -SteamPath 'C:\Program Files (x86)\Steam\steam.exe' `
  -CS2Path 'C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive\game\bin\win64\cs2.exe'
```

Если Steam/CS2 ещё не установлены, параметры путей можно опустить: агент будет
собирать телеметрию и выполнять синтетические тесты. В панели Nodes создайте
одноразовый токен привязки и введите его в защищённое приглашение установщика.
Токен не передаётся в аргументах процессов. Установщик создаёт защищённый
одноразовый файл, запускает регистрацию под LocalSystem и удаляет файл.
Затем создаётся автоматически запускаемая служба `CS2FarmAgent` с восстановлением
после сбоя. Не передавайте enrollment token через журнал или Telegram.

Файлы:

- `%ProgramFiles%\CS2FarmAgent\current` — код агента и движка.
- `%ProgramFiles%\CS2FarmAgent\venv` — отдельное окружение Python.
- `%ProgramData%\CS2FarmAgent\config.json` — локальная конфигурация.
- `%ProgramData%\CS2FarmAgent\credentials.dat` — Node ID и DPAPI-защищённый токен.
- `%ProgramData%\CS2FarmAgent\journal.sqlite3` — журнал команд и владения PID.
- `%ProgramData%\CS2FarmAgent\agent.log` — ротируемый журнал (5 MiB × 5 файлов).

ACL допускают SYSTEM, владельца и локальных администраторов. Учётные данные DPAPI
может расшифровать тот же системный пользователь, который выполнил регистрацию.
Запуск console-agent с учётными данными службы под другим пользователем не
поддерживается. Для переноса на другой компьютер нужно отозвать старый Node и
создать новую привязку.

```powershell
Get-Service CS2FarmAgent
Get-Content "$env:ProgramData\CS2FarmAgent\agent.log" -Tail 50
Restart-Service CS2FarmAgent
```

Для удаления:

```powershell
.\apps\windows-agent\installer\Uninstall-Agent.ps1
```

Данные сохраняются. Удаление локальных данных требует `-RemoveData`; доступ узла
также следует отозвать в панели.

## Локальное тестирование на Linux

Linux поддерживается только для проверки протокола, телеметрии и синтетического
движка. Запуск Steam/CS2 отклоняется. Из корня репозитория:

```bash
uv pip install --python .venv/bin/python -e apps/windows-agent -e packages/gameplay-test-engine
```

Пример `/tmp/farm-node/config.json` (каталог создайте заранее):

```json
{
  "server_url": "http://127.0.0.1:8000",
  "data_dir": "/tmp/farm-node",
  "heartbeat_seconds": 5,
  "test_capacity": 4,
  "allow_insecure_localhost": true
}
```

```bash
.venv/bin/python -m agent.main --config /tmp/farm-node/config.json --enroll
.venv/bin/python -m agent.main --config /tmp/farm-node/config.json
```

HTTP разрешается только для явно включённого localhost. Остальные адреса требуют
HTTPS, сертификат проверяется системным trust store. Для собственного CA установите
его в trust store агента; проверку сертификата отключать не следует.

WebSocket находится на `/ws/agent`, REST enrollment на `/api/v1/nodes/enroll`.
Повторное подключение использует экспоненциальную задержку 1..60 секунд с jitter.
Heartbeat — каждые 5..15 секунд. GPU определяется через доступный `nvidia-smi`;
недоступные GPU/temperature-показатели передаются `null`.

## Восстановление и безопасность команд

Перед запуском фиксируются Command ID и хеш всего запроса. Повторный ID с теми же
параметрами возвращает сохранённый результат; с другими параметрами отклоняется.
Каждая команда имеет обязательный deadline с UTC-смещением. Запуск с истёкшим
сроком отклоняется даже после удаления старой записи из журнала.

PID дополняется временем создания процесса. Чужой процесс с повторно использованным
PID не считается управляемым. Windows Job Object завершает принадлежащие агенту
деревья при аварийном выходе агента. При отключении сети работающие процессы
продолжают выполняться; сервер резервирует узел состоянием UNKNOWN. При
переподключении агент сначала отправляет последние сохранённые ACK, включая
завершения во время потери сети, затем текущие процессы. Отсутствие exit code
после перезапуска агента сообщает ошибку, а не фиктивный успех.

`restart_agent` отклоняется, если есть управляемые сеансы. В режиме службы
подтверждённый перезапуск использует настроенную SCM recovery policy. В консоли
агент завершится с кодом 75, поэтому нужен supervisor для автоматического старта.

Терминальные записи команд и журналы завершённых процессов удаляются через 30 дней.
Незавершённые команды не удаляются автоматически. Журнал агента и диагностические
ошибки команд отправляются серверу без токенов и авторизационных заголовков.

## Подписанные обновления

Агент проверяет Ed25519-подпись manifest и SHA-256 архива, ограничивает размер
архива и распакованных файлов 100 MiB, отклоняет zip traversal, symlink и другие
опасные имена. Разрешены только HTTPS и локально закреплённый update host;
редиректы не разрешены. Запрещены downgrade и переустановка той же версии.

Manifest:

```json
{
  "version": "0.2.0",
  "url": "https://updates.example.com/agent-0.2.0.zip",
  "sha256": "<hex sha256>",
  "signature": "<base64 Ed25519 signature>"
}
```

Подписывается UTF-8 JSON полей `version,url,sha256` с `sort_keys=True` и
`separators=(',', ':')`. Закрытый ключ хранится офлайн и не передаётся серверу
или агенту. Создать manifest можно:

```bash
python apps/windows-agent/installer/Sign-Release.py \
  --archive agent-0.2.0.zip --private-key offline-ed25519.pem \
  --version 0.2.0 --url https://updates.example.com/agent-0.2.0.zip \
  --output manifest.json
```

Корень ZIP должен содержать `agent`, `collectors`, `process_manager`, `transport`,
`security`, `installer` и `gameplay_test_engine`. Release должен быть совместим с
уже установленными Python-зависимостями: обновление зависимостей выполняется
администратором отдельно. Измените защищённый `config.json` локально:

```json
{
  "update_public_key": "<base64 raw 32-byte Ed25519 public key>",
  "allowed_update_host": "updates.example.com",
  "update_manifest_url": "https://updates.example.com/manifest.json",
  "automatic_updates": true,
  "update_check_seconds": 3600
}
```

Поля добавляются к основной конфигурации. Перезапустите службу. Автопроверка
выполняется только при отсутствии управляемых сеансов. Если сеанс появился во
время загрузки, активация откладывается. После проверки фиксированный локальный
PowerShell-установщик останавливает службу, перемещает `current` в `previous`,
активирует release и запускает службу. При ошибке запуска возвращается предыдущая
версия. Предыдущий каталог сохраняется для ручного отката.

Для ручной проверки и подготовки обновления (без активации):

```powershell
& "$env:ProgramFiles\CS2FarmAgent\venv\Scripts\python.exe" -m agent.main `
  --config "$env:ProgramData\CS2FarmAgent\config.json" `
  --stage-update https://updates.example.com/manifest.json
```

Затем выполните `installer\Apply-Update.ps1 -Release <путь_проверенного_release>`
от администратора. Сам по себе центральный сервер не может заменить закреплённый
ключ и не предоставляет произвольное удалённое выполнение команд.
