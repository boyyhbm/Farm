# Подключение агента через Windows Desktop

Desktop Agent использует существующий Agent, его журнал идемпотентности, psutil-телеметрию, ограниченный список операций и безопасное завершение дочерних процессов. В рабочем пользовательском сценарии Python, команды и редактирование JSON не требуются: Electron передаёт настройки встроенному `farm-runtime` через stdin и запускает его без окна консоли.

## Мастер подключения

1. На главном компьютере создайте одноразовый код привязки в Nodes.
2. Установите отдельный Agent Installer на дополнительный ПК и откройте приложение.
3. Введите HTTPS-адрес сервера и одноразовый код. Если используется собственный CA, импортируйте его PEM-сертификат только из доверенного источника. Сверьте имя сервера и происхождение сертификата.
4. В разделе приложений агента выберите установленные `steam.exe` и `cs2.exe` через графический выбор файла. При первоначальной привязке стандартная установка Steam определяется из реестра Windows и Program Files, CS2 — из стандартной библиотеки Steam. Другие библиотеки выбираются вручную через GUI. Пустой путь означает, что приложение недоступно. Произвольные имена файлов, относительные/несуществующие пути и аргументы запуска запрещены.
5. Подтвердите автозапуск приложения при входе в Windows. После регистрации дождитесь действительного heartbeat в Node Manager.

Мастер не сохраняет одноразовый код. Постоянный credential хранится в `credentials.dat` с DPAPI и ACL текущего Windows-пользователя; возвращаемый оболочке результат содержит только Node ID и статус. Существующий credential нельзя молча заменить — сначала отзовите прежний узел в панели.

Изменение путей сохраняется атомарно с ACL и вступает в силу после перезапуска агента оболочкой. Удалённый файл отображается как недоступный; приложение не подменяет этот статус успешной установкой.

## Защищённое соединение

HTTP в desktop-мастере запрещён, включая удалённый или локальный `http://`. Запрещены URL с логином/паролем, query и fragment. HTTPS/WSS всегда проверяют сертификат и имя сервера. Импортированный CA дополняет стандартные доверенные корни; `verify=False` не используется. Не выполняется открытие портов или добавление правил Windows Firewall. Сервер должен иметь защищённый доступ, настроенный в графическом мастере главного приложения либо уже существующий HTTPS-доступ.

Переподключение после сетевой ошибки использует backoff и jitter. Отзыв credential прекращает автоматические попытки, требуя нового кода. Привязка и события команд сохраняются отдельно от transport; повтор команды не запускает процесс второй раз.

## Автозапуск и идентичность

Desktop Agent работает в интерактивном Windows-сеансе пользователя и запускается после его входа в Windows, если включён автозапуск оболочки. Он **не** запускает Steam до входа пользователя и не подменяет полноценную системную службу. Такой режим позволяет штатно показывать Steam/CS2 на рабочем столе и выполнять ручную авторизацию официального клиента.

Ранее созданная Windows Service остаётся доступной для управляемых развёртываний. Она использует LocalSystem и отдельно привязанный DPAPI credential; переносить между desktop и service их `credentials.dat` нельзя. Desktop Installer и API не отключают Steam Guard и не переключают Steam-пользователей автоматически.

## Проверки

Linux unit-тесты проверяют безопасные URL, CA/hostname verification, отсутствие кода в конфигурации, отсутствие credential в ответе мастера, отказ от замены прежней привязки, неуспешную регистрацию, команду запуска упакованного тестового движка, атомарное сохранение разрешённых путей, отказ от произвольных файлов и корректное отображение удалённого приложения. Дополнительный тест выполняет настоящий TLS handshake с доверенным тестовым CA и подтверждает отказ без этого CA. Установка/автозапуск на настоящей Windows и работа после её перезагрузки требуют Windows CI/физического стенда; Linux не объявляется такой проверкой.
